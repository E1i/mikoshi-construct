# 0.43.0 — Mikoshi builds the Atlas of any repository

0.43 gives Mikoshi one new capability: `construct atlas` builds the Atlas of any repository. It is not
a document about Mikoshi itself. Mikoshi builds its own Atlas with the same command, the same
discovery and the same page as it builds anyone else's, and nothing in that command knows which
repository it is reading.

One call does three things. Discovery reads what git tracks. What discovery found goes into the
Engram. The Atlas page is rendered from the Engram as one self-contained HTML file, which needs no
network and opens from disk. The Engram is the input and the Atlas is the view derived from it. They
are not two competing pictures of your repository.

## If you are upgrading, do this first

1. **Upgrade every `construct` that reads your `construct.model.json` before you write it with 0.43.**
   0.43 writes the model as `modelVersion` 5, whether through `atlas` or `init`. A 0.42 or older
   build that meets that file, a global `construct` or a CI step pinned to an older version, refuses
   it as written by a later build. That refusal is correct, but it looks like breakage.
2. **Replace `construct graph --out`.** The option is gone, and the page you open is now the Atlas:
   run `construct atlas`, or `construct atlas --out <path>`. `construct graph` still prints Mermaid
   text, unchanged.
3. **Expect most of your first Atlas not to be painted held.** A node is painted held only when a
   test report that covers it was read here and its covering tests passed. A node that stands only on
   what the repository's files say is an assumption, not a confirmation. A node that is not held is
   the Atlas telling you what nothing proved. It is not a fault in your repository.

## Where the Atlas goes

| Repository | Engram | Page |
|---|---|---|
| made by `init` | `construct.model.json`, its `mechanics` replaced, every fact, claim and node kept | `.construct/atlas.html`, plus `atlas-docs.html` beside it |
| attached by `attach` | `~/.construct/engram/<repo>-<hash>/construct.model.json` | `.construct/atlas.html` |
| neither | `~/.construct/engram/<repo>-<hash>/construct.model.json` | `~/.construct/engram/<repo>-<hash>/atlas.html` |

## The Atlas also works in attach mode

You do not need `init` to get an Atlas. In a repository Mikoshi only attached to, `construct atlas`
keeps the Engram in your home directory, outside the tree. The page goes to `.construct/atlas.html`,
in the directory `attach` already excludes through `.git/info/exclude`. `git status` after `atlas` is
as clean as it was before. `construct detach` removes the page along with the other files the
construct put into `.construct/`.

An attached repository gets the map only. The Docs view, which reads the same Engram stage by stage,
is written only into a repository `init` made, because the Atlas writes no documentation into a tree
it does not own.

## What discovery reads

- **Every tracked file is a node.** A file whose type discovery does not read keeps its place on the
  map. Its relations are `unknown`, and its reason (`type-not-scanned`) is shown beside its colour, so
  an unread file is not mistaken for a file with no links.
- **Imports are read through named adapters.** The TypeScript/JavaScript reader is the first one.
  `sfc-script` reads the `<script>` blocks of `.vue`, `.svelte` and `.astro` single-file components,
  and an Astro-style leading `---` fence.
- **Non-relative imports resolve through the repository's own configuration.** These are the `paths`
  of the nearest `tsconfig.json` or `jsconfig.json`, and the workspace packages that
  `pnpm-workspace.yaml` or the `workspaces` of `package.json` list. A specifier that no configuration
  names, such as an npm dependency, is left out.
- **An import of a file of a type discovery does not read** resolves to that file. It no longer
  refuses the whole Engram.

## What the probes found

Two read-only probes ran `attach → atlas → detach` on four live repositories, here called A–D. Both
probes also took a snapshot before and after. This note names nothing else about those repositories.

**The first probe, at the first `construct atlas`: the Atlas was built on none of the four, and not
on Mikoshi itself either.** On all four, one import of a file that was not a component aborted the whole Engram,
and the page was never written. Discovery itself read each tree in 73–264 ms. The trace guarantee
held: the snapshots before and after `detach` matched on B, C and D, and on A, where only `atlas` ran
because an earlier attach was in place, `atlas` left nothing either. The probe found three gaps:

- the abort itself;
- `.vue` and `.astro` single-file components were not read at all;
- path aliases and workspace packages were dropped, which on the monorepos lost most cross-package
  links.

**The rerun, after the fixes and the three discovery changes above: the Atlas was built on 4 of 4,
and `attach → atlas → detach` left no trace on 4 of 4.** The three gaps from the first probe no longer show.
Here is what is still empty or unknown:

- **25 of 15716 relations are unknown.**
  - **14 come from gaps in the resolver.** Each one is a directory index reached through `./` or
    through an alias that ends in `/`, a target that exists only as a `.d.ts`, or a bundler query
    suffix such as `?inline` that is not stripped. A later adapter or resolver change would turn
    these into relations.
  - **11 point at files that are not in the tree**: stale imports, files outside the repository, and
    framework-generated untracked files. These are correctly unknown, and no adapter would change
    them.
- **2130 files are on the map with relations `unknown`, because discovery does not read their
  type.** Among them:
  - stylesheets (196, whose `@import` and `url()` are not read);
  - `.html` (35) and `.sql` (82);
  - data and configuration (`.json`, YAML, TOML and the like);
  - assets and documentation (`.svg`, images, `.md`) where no relation is expected.

  For these files the map shows that they exist, but not what they link to.

**Mikoshi itself, at the same commit:** 1599 tracked files, 834 of them of a type discovery does not
read. 6318 relations, 10 of them unknown. All 10 are imports inside `templates/` whose target exists
in the repository only as an `.eta` source, which `init` renders into the file the import names.

## Everything else in 0.43

- **`detach` leaves no trace of the guest.** A `.claude/settings.local.json` that existed before
  `attach` comes back byte for byte. The ladder's runtime files and the browser-lab runs the guest
  created are removed. What was there at attach stays. A repository attached by an earlier build
  has no record of what was in `.construct/browser`, so its run directories there stay.
- **Intake:**
  - a parked card records the paths it `creates:`;
  - `--admit` amends a card whose only change is its `touches`;
  - `--move` moves a parked card between parking directories;
  - a witness whose `-t` argument is not a valid regular expression is refused;
  - removing a dependency the journal shows merged needs no person's confirmation.
- **`construct mutate judge`** refuses a report in which no test ran, or in which the named test was
  skipped.
- **A brief's Invariant command** keeps the spaces inside its backticks as written.
- **Templates:**
  - the browser lab keeps a `--profile` across runs and lists an extension service worker's requests
    with `network`;
  - a generated project pins typescript-eslint to 8.71.0 until a release that fixes
    typescript-eslint#12980 is older than a day;
  - the `/implement` ladder keeps a verified diff when the base moves under it, re-running only the
    witnesses the base change touches, and stops with `base moved` only after the base moved more
    than twice.
