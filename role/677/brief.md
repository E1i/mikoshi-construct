- 2. (a) What attach records. `record.ts` gains the optional field `browserHeld?: string[]` on `AttachRecord`; `carriers.ts` gains `browserEntriesHeldAtAttach(root)`, the sorted names inside `.construct/browser` at attach, `[]` when it is absent or not a directory; `attach/index.ts` calls it beside `runtimeHeldAtAttach`, before anything is written, and writes the result as `browserHeld`. `ATTACH_RECORD_VERSION` stays 2: the field is additive and optional. `runDetach` refuses only a `recordVersion` above its own (`version > ATTACH_RECORD_VERSION`, the `record-ahead` path), so a bump to 3 would make every earlier detach refuse this record and remove nothing; an earlier detach reads the new record as version 2, ignores the field, and keeps slice 1's reading (held browser, none removed), which is safe. A record written before the field existed has no list and is read the same way.
- 3. (b) Which run directory is the guest's. `classifyRuntime` takes run directories when `.construct/browser` was absent at attach (`browserFree`: every matching run, as today), or when the record has the array `ledgerHeld`, the browser was held (`!browserFree`) and the record has `browserHeld` as an array of strings (`guestRunsOnly`): then a run goes only if its name is not in `browserHeld`. There is no comparison with a clock — no `attachedAt`, no name stamp, no mtime — so a directory that existed before attach stays whatever its mtime or the time in its name. A record without `ledgerHeld` or without `browserHeld` keeps slice 1's reading: held, so none removed. Every other filter stays: the name matches `ATTACH_RUNTIME_RUN_DIRECTORY`, the entry is a directory, every entry is a regular `*.png`, none is tracked. `.construct/browser` itself is removed only when `browserFree`, so the held directory stays and `detachLeftBehind('.construct/browser')` still prints. A host file such as `.construct/browser/notes.txt` stays.
- 4.
