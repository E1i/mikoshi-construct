The schema (`src/model/schema.ts`). `MODEL_VERSION = 5`; `RepositoryModel.mechanics?: Mechanics`, listed in `MODEL_PROPERTIES`, parsed only when present and absent from the result otherwise, so every older document and every existing `toEqual` reads as before. `Mechanics { identity: { sha: string | null, status, source: CommandSource }, tree: { status, source: CommandSource }, components: { id, path }[], relations: { from, to: string | null, kind: 'imports' | 'calls', specifier, status, source: LineSource }[] }`, `CommandSource { command, exit: number | null, effects: string[] }`, `LineSource { path, line ≥ 1 }`, `status` one of `OBSERVED_STATUSES = ['found', 'unknown']`. Closed like the rest: exported property lists `MECHANICS_PROPERTIES`, `IDENTITY_PROPERTIES`, `TREE_PROPERTIES`, `COMMAND_SOURCE_PROPERTIES`, `LINE_SOURCE_PROPERTIES`, `COMPONENT_PROPERTIES`, `RELATION_PROPERTIES`; component ids unique; a relation's `from` and a found relation's `to` name a declared component; an `unknown` relation has `to: null`. A component has no `stage`, no `supportedBy` and no state, and nothing in `state.ts`, `graph.ts` or `doctor` reads `mechanics`.
- 5. The scan (`src/model/scan.ts`, pure). `maskComments(source)` returns two same-length copies, comments blanked in both and string contents also blanked in the second, newlines kept. `scanModule(source)` finds `import … from`, `export … from`, `import '…'` and `import('…')` on the string-blanked copy and reads the specifier from the other at the same offsets, so an import inside a comment or a string is not one; it collects the value bindings (default, named, `* as ns`; `type` imports and re-exports bind nothing) and finds `name(` and `ns.member(` calls on the string-blanked copy, each with its 1-based line.
- 6. Discovery (`src/model/discovery.ts`). `discoverMechanics(root, readings = readGit(root))`: identity `found` only when `rev-parse` exits 0 with a full hex sha, else `sha: null, status: 'unknown'`; tree `found` only when `ls-files` exits 0, else no components; components are the tracked files ending `.ts .tsx .mts .cts .js .jsx .mjs .cjs`, `id = path`, sorted by byte order; relations only for relative specifiers (a bare one is outside the repository), resolved against the tracked set by a fixed candidate order (as written, `.js→.ts/.tsx/.js/.jsx`, `.mjs→.mts/.mjs`, `.cjs→.cts/.cjs`, then `.ts .tsx .js .jsx .mjs /index.ts /index.tsx /index.js`), `to: null, status: 'unknown'` when none is tracked, and a call relation inherits its import's target; deduplicated and sorted by `from`, line, kind, specifier, `to`. No time, no absolute path, no locale compare.
- 7. Where the Engram goes (`src/model/discovery.ts`). `engramFile(root, { attached, home })` is `<home>/.construct/engram/<basename(root)>/construct.model.json` when attached and `<root>/construct.model.json` otherwise (`ENGRAM_HOME_DIR = '.construct/engram'`). `writeEngram(root, place, mechanics = discoverMechanics(root))` reads the document at that path if there is one (else an empty model), replaces only `mechanics` and `modelVersion`, checks the text with `parseModel` before writing, creates the directory and writes it; an attached target gets no byte.
