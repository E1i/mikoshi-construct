Design:
1. The touched set is exactly: scripts/shift/shard.ts (new), scripts/shift/shift.ts, scripts/tests/shift/shard.test.ts (new), package.json, CONTRIBUTING.md, tests/harness-membership.test.ts, architecture/owner-merges.md. scripts/shift/merge.ts is not changed: the delegation reads runMerge's lines as they are.
2. `runShard(argv, deps)` in scripts/shift/shard.ts is `pnpm shard <shift dir> [--by <name>]`: `by` is `--by`, else `git config user.name`, and an empty issuer is refused; `run` is the directory resolved against cwd; `id` is a randomUUID. It appends one `{"event":"shard","id","by","ts","run"}` line to `<handoff>/ghosts.jsonl` (`CONSTRUCT_HANDOFF_DIR`, else `~/.construct/handoff`) and prints `[shard] shard <id> issued by <by> for <run>; pnpm shift <run> --slot <id>`. A wrong argument count prints the usage and exits 1. Deps are injected (cwd, handoffDir, append, now, uuid, by, out, err) like ShiftDeps.
3. `slotRefusal(root)` in shard.ts is the INIT rule the owner settled, with no new state: `readAttachRecord(root) !== null` refuses (`.construct/attach.json exists: the run is not INIT (attach)`), then `readManifest(root) === null` refuses (`construct.json does not exist`), and a throw from either refuses with its first line. `shardRefusal(journal, id, run)` refuses a journal with no `shard` line of that id, a shard whose `run` is another directory, and a shard with a `shard-used` line of that id (`shard <id> was used once already; a shard is spent when its run ends`). `usedLine(id, run, now)` is `{"event":"shard-used","id","run","ts"}`.
4. `runShift` in shift.ts takes `--slot <id>` beside `--parking` (both valued flags filtered from the rest; a missing value prints the usage line). With `--slot`, `slotRefusal(deps.cwd) ?? shardRefusal(<handoff>/ghosts.jsonl, id, dir)` runs right after the usage check, before the `shift.jsonl` exists check and before sweepMerges, and a refusal is `[shift] --slot: <reason>; nothing started`, exit 1. The `shard-used` line is appended to ghosts.jsonl after every refusal (so a refused run spends nothing) and before the `start` line of shift.jsonl and the first card; one shard covers the whole run, the chain, and is spent with it. USAGE's first line stays byte for byte (autopilot-docs.test.ts and shift.e2e.test.ts w9 pin it); `[--slot <shard>]` gets its own row after `[--manual]`, and three lines after the autopilot line say what --slot does.
5. `mergeLines(deps, task, number, text, delegation)` in shift.ts replaces the inline expression in mergeFromReport: a report that asks the owner (asksTheOwner) is not armed, as today; otherwise runMerge's lines via mergeAfterSession; the shard applies only when a shard is held and every line ends `merge is Eli's` (decision owner or an owner-merged path; a runMerge refusal, which ends `auto-merge not armed`, is never delegated). A session whose last exit is `guard-refusal` appends `PR #N a guard refused in the session; shard <id> not applied, merge is Eli's`; otherwise delegatedMerge's lines are appended. The shard and the guard flag are threaded runShift → runTask / runLadder → finishTask → mergeFromReport, so the ladder's review step takes the same path.
6. `delegatedMerge(deps, task, number, shard)` in shard.ts: `gh pr view <N> -R E1i/mikoshi-construct --json headRefName,headRefOid`; a head matching `^changeset-release/` is `PR #N is a version pull request (<head>) and stays the owner's; shard <id> not applied, merge is Eli's`; then `prDetails(gh, REPO, pr).ci` from scripts/board/gh.ts — `red` or `unknown` is `PR #N required checks <ci.text>; shard <id> not applied, merge is Eli's`; `pending`, `green` or `none` arms `gh pr merge <N> --auto --squash --match-head-commit <oid> -R E1i/mikoshi-construct`, appends `{"event":"delegated","task","pr","shard","why":"owner decision delegated, shard <id>","ts"}` to ghosts.jsonl and returns `[shift:merge] owner decision delegated, shard <id> — auto-merge armed on PR #N at <oid>`, which MERGE_ARMED matches so no stop is written. Every not-applied line leaves stopAfter to write `at: merge` (or `fault` for the guard refusal, `question` for a question) with the lines as `why`, appended to the report as today. A check that turns red after arming is #652's.
7. scripts/tests/shift/shard.test.ts runs on fixtures/autopilot-world.ts (temp git origin, temp handoff journal, claude-stub-pr.sh) with this repository's construct.json copied into the world's tree for INIT, and a gh stub wrapping fakeGh that answers the `headRefName,headRefOid` and `headRefOid,statusCheckRollup,files` views; no test calls real gh or touches ~/.construct. The card's six titles are kept exactly, plus `pnpm shard writes one shard line naming who, when and the run`, `a guard refusal with a shard stops`, `red required checks with a shard stop at merge` and `unknown required checks with a shard stop at merge`.

Registries, in the same change: package.json `"shard": "tsx scripts/shift/shard.ts"` after `shift:report`; CONTRIBUTING.md § Scripts a `pnpm shard` row after `pnpm shift:report` (what it writes, what --slot refuses and arms, that it is a record of intent and not a security boundary) and `[--slot <shard>]` in the `pnpm shift` row's usage cell, written `[--parking <parking>] [--slot <shard>] [--check] [--queue] [--manual]` so the pinned `[--queue] [--manual]` stays; `'shard'` in OUTSIDE_THE_HARNESS in tests/harness-membership.test.ts; `scripts/shift/shard.ts` in the `own-instructions` cell of architecture/owner-merges.md with the history sentence `On 2026-10-08, at Eli's instruction (task #650), it added scripts/shift/shard.ts to own-instructions: with a shard the shift arms auto-merge on an owner pull request on its output.` (scripts/tests/shredder/owner-merges.test.ts requires every scripts/shift file naming a merge there).
