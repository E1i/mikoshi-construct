templates: `/plan` gains the brief and witness rules: the Design and the Invariants must not contradict each other; a Design names every file its own decisions force; each witness is run as the ladder runs it (`bash -n`, red on the base for a behavioural reason, green on a known solution where one exists) before approval, and a changed brief goes back for a new approval; the fixtures its witnesses run against are merged before the ladder starts; a block of witness-writing rules; producer and consumer order by what passes between them (a data format: the reader first; a behaviour: the consumer last); deferrals, import rules for a new module, half-done migrations and verifications each get a task of their own; and a `high` task is planned as its design step followed by `medium` implementation tasks carrying the settled design. The implement skill states where a ladder may start (the task's own worktree, never after `EnterWorktree`), links `high` to the design it requires, and keeps the tree read-only after `done`. The security invariants header and discovery step 10 require `Enforced by` to name the mechanism and what it matches, never a bare tool name.
