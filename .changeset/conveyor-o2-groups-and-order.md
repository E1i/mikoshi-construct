Adds the overlap model and the `pr_order` order of pull requests, and runs it in the bus. `scripts/core/order/overlap.ts` decides when two path sets overlap: they share a path once derived registries are removed, or they meet the same declared contention area. `group.ts` turns that into groups of open pull requests. `turn.ts` folds the new `pr.ordered` event into the `pr_order` projection, derives `turnOf` for a group, and counts `needsUpdate` and `needsVerification` in shadow. The turn skips a member parked on a `changes` verdict, red CI, a queued or leased answer, a card hold or an open owner question, and goes to a member holding a leased update or merge; a pull request not observed yet is grouped by its card's declared touches. `needsUpdate` holds on GitHub `dirty`, on a path overlap with what main changed since the head, on a truncated main, and on CI red on the pull request while green on main; the bus records no CI of main yet, so that last condition counts nothing in the running bus until O3 (#1916), the slice that first acts on `needsUpdate`, records it. The supervisor runs this fold on every tick: it writes `pr.ordered` once per life of a pull request, when it first reaches pass + green, prints the shadow counts, which nothing acts on yet, and records each change of the groups, their turns and the shadow counts as a `pr.groups` event. The board's services screen reads the latest `pr.groups` and shows each group with its modules and its turn, and the shadow counts, so the product build carries no bus code. The window request `order.move --pr <N> [--before <N>]` writes `pr.ordered {before, by: window}`, which moves the pull request ahead of the one it names, or to the tail. `importClosure` moved from the supervisor to `scripts/core/import-closure.ts`. `scripts/core/order/` is the new module `order`, `import-closure.ts` belongs to `session`, and session and window may use `order`.
