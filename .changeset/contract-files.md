`contract/factory.json` now has a `files` section: every file and table the factory keeps in the home directory or under `.construct/` gets an entry naming its owner module and its single source. The entries are generated by `scripts/contract/factory/files.ts`. Generation fails, and so does CI, when a file has no entry or when a file has two writer modules. `lane.json` and `owner-decisions.md` are recorded as derived views: the first of the `lane.assigned` event, the second of the `decisions` table. Each is owned by the one writer of its source.

`contract/factory.json` also has a `globals` section, generated by `scripts/contract/factory/globals.ts`. It is the explicit list of global files (`package.json`, the lockfile, the workspace, the tsconfigs, `.npmrc`, `.nvmrc`), and only these take the full run. `selectRun` and `cardRunsOf` read the same list and give the same reason. The implicit rule that every root config or workflow takes the full run is gone. A root config read by one tool goes to that tool's layer in `scripts/core/layer-map.json`, so `.dependency-cruiser*` goes to `ci`. `SECURITY.md` and `CODE_OF_CONDUCT.md` go to the docs layer. A tracked file that is in no layer and not in the list fails `scripts/tests/core/layer-map.test.ts`.
