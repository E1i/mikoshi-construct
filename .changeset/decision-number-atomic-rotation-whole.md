`decisions:add` no longer gives one number to two decisions or leaves the decisions files in a state that blocks every later decision. It holds an exclusive lock file, `owner-decisions.md.lock`, while it reads both files, picks the next number, writes, and records the decision in the bus. A second `decisions:add` waits up to five seconds for that lock, then stops and writes nothing. The refusal names the process holding the lock and says to remove the lock file if no `decisions:add` is running. A failed add restores only a file that still holds what it wrote, so it never erases what another writer put there. When older decisions move to the archive, every record of a number moves together, or none of them do, so one number never ends up in both the working file and the archive. `--supersedes D-N` now retires every record of D-N. A number that appears twice is refused with the command that resolves it: `pnpm decisions:add --supersedes D-N "[owner] …"`. Rebuilding the decisions file from the bus keeps both files unchanged if the rebuilt files would fail the check.
