The bus is read through one port, `scripts/ports/bus-read.ts`. A reader asks it for a slice of one event type with the payload fields it needs, and a field the event's contract does not declare is refused. A projection that is behind its events reads stale, through the watermark in `scripts/core/bus-readings.ts`, instead of answering with old rows. The port writes nothing. The board page's gauges and shard decisions, and the window's equivalence ticks, now read through it. A new concept, `bus-read`, counts every other SQL read of a bus table, and the ratchet only lets that count fall. Each moved reader returns what it returned before: the shard decisions are the newest twenty with a stop, the newest first; a card whose newest heartbeat is not JSON is left off the gauges; legacy equivalence ticks still count. Two readers the card named are not moved yet. `src/commands/board/bus.ts` may import only `scripts/core/bus-readings.ts`, and core may not re-export a port. `src/commands/doctor/factory.ts` runs no SQL of its own: it reaches the bus through `factoryLiveness`, which stays outside the port (§10a), and through the decisions file. Where the port should live so that `src/` can read through it is a question for the owner.
