# Security invariants

Security is its own review dimension. Each invariant names what enforces it; `review` means the
reviewer is the only check, so weigh those the most. `Enforced by` names the mechanism and what it
matches (the lint block and its selectors, the test file, the workflow job), never a bare tool name
such as `lint`, `CI` or `tests`, and it changes in the same change as the mechanism. A finding that recurs is an architectural
problem: move the protection to a shared boundary and add a check rather than fixing the symptom
again. Method: [principles.md § Security](principles.md#security).

The baseline rows below are enforced by files this construct materialized. Discovery adds the rows
that are specific to this system — the ones where money, identity or data can be corrupted.

| Invariant | Enforced by |
|-----------|-------------|
| No secret, token or connection string in any file, including gitignored ones; config references `${VAR}` placeholders | `.github/workflows/security.yml` runs gitleaks over the history on every push and pull request (`.gitleaks.toml` keeps the default ruleset live); review |
| Dependencies with known high-severity vulnerabilities are visible | `security.yml` runs `pnpm audit` weekly and on pull requests, reporting only |

| In a repository `construct attach` is attached to, the agent's own `git commit`, `push`, `merge`, `rebase` or `tag` is refused with exit 2 (decision 0035): the direct form, after `git -C` / `-c` / `--git-dir`, a leading `cd`, a subshell, an assignment and the wrappers `env` (its `-S` string included), `nice`, `sudo`, `timeout` and `xargs` under any path, each word read after quotes, escapes, `$'…'` and `$"…"`; a target it cannot pin down is refused as unpinned. Not guaranteed: a commit inside a script, an alias, a function, `eval`, `bash -c` / `sh -c`, a subcommand that `xargs` or a variable supplies, any other tool, or a host without `node` | L2, the `PreToolUse` hook `.construct/commit-guard.mjs` (source `templates/attach/_construct/commit-guard.mjs`, which reads the command line through `.construct/shell-parser.mjs`, source `templates/attach/_construct/shell-parser.mjs`); `tests/commit-guard.test.ts` holds a refused row per wrapper and spelling and a passing row per named boundary (`eval`, a script, `bash -c`, `xargs git`) |
| A hook script reads its stdin to the end and never swallows a read error: its parent may write the input late, in pieces or large. | A factory guard hook — `.claude/hooks/role-guard.mjs guard` and `.claude/hooks/eddies.mjs guard`, the `PreToolUse` hooks of this repository — lets a call through only by an explicit exit 0: a module that fails to load, a config, transcript or subagent transcript it cannot read, an input without an absolute `transcript_path`, a `CLAUDE_PROJECT_DIR` that is not a directory, or any exception refuses with exit 2 and one stderr line, because Claude Code 2.1.288 lets a call through on exit 1, a crash or a timeout. The named allowances are a tool other than `Agent` (role-guard), a session that started before the snapshot (role-guard), a session transcript not created yet, and an agent with no transcript under its session (eddies). Not guaranteed: the hook process killed by the 5 s timeout, `node` missing, or the hook file itself failing to parse — Claude Code lets each of those through | `tests/role-guard.test.ts` refuses with a missing and a throwing `role-definitions.mjs` beside a copy of the hook; `tests/eddies.test.ts` holds one refused row per unmeasured cause and an allowed row per named allowance; a call refused on live Claude Code events is review-level |
| The commit guard lets a call continue only by an explicit exit 0 on the path where its decision found nothing to refuse; every other outcome refuses with exit 2, because Claude Code runs the call on any exit other than 2 (observed on Claude Code 2.1.288, probe #118): input that is not JSON or not a JSON object and an exception while checking the call end in one line on stderr, and a crash anywhere else after the listener is registered ends in exit 2 with Node's own trace on stderr; the parser is imported inside the checked call, so a missing or unloadable `.construct/shell-parser.mjs` ends in one line on stderr and exit 2. Not closable from inside the hook: a run longer than the hook's `timeout` (30 s for the commit guard) is killed by Claude Code and the call runs; an error before the file's first statement runs — the file missing, a syntax error, a `node` that cannot parse it — and a host without `node` end in a non-blocking exit and the call runs | `templates/attach/_construct/commit-guard.mjs` writes its exit code in one place, an `exit` listener that reads `verdict.allowed`; `tests/commit-guard.test.ts` spawns the installed guard over text that is not JSON, a JSON array, JSON null and a `git commit` whose `$(` nesting overflows the scanner's stack, and asserts exit 2 with one stderr line for each; `tests/commit-guard-parser.test.ts` removes the parser and asserts the same for a commit and for an ordinary call |
| `attach` writes outside the target tree in exactly one place, the pre-image of a host `.claude/settings.local.json` at `~/.construct/attach/<key>/settings.local.json.orig` (mode 0600, directory 0700); `detach` restores it after a sha256 check and removes it, and refuses without writing when the copy does not match | `tests/attach.test.ts` ('mode 0600', 'original-pending') and `tests/detach.test.ts` (the restore, refusal and path-confinement tests); that this is the only write outside the target tree is review-level |
