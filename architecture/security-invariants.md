# Security invariants

Security is its own review dimension. Each invariant names what enforces it; `review` means the
reviewer is the only check, so weigh those the most. A finding that recurs is an architectural
problem: move the protection to a shared boundary and add a check rather than fixing the symptom
again. Method: [principles.md § Security](principles.md#security).

The baseline rows below are enforced by files this construct materialized. Discovery adds the rows
that are specific to this system — the ones where money, identity or data can be corrupted.

| Invariant | Enforced by |
|-----------|-------------|
| No secret, token or connection string in any file, including gitignored ones; config references `${VAR}` placeholders | `.github/workflows/security.yml` runs gitleaks over the history on every push and pull request (`.gitleaks.toml` keeps the default ruleset live); review |
| Dependencies with known high-severity vulnerabilities are visible | `security.yml` runs `pnpm audit` weekly and on pull requests, reporting only |

| `init` never overwrites a file it did not create: existing files are skipped, `package.json` is merged with existing keys winning, `CLAUDE.md` / `AGENTS.md` / `.gitignore` are edited only inside their `construct:begin … end` block, filled discovery blocks are carried over | `tests/strategies.test.ts`, `tests/init.test.ts` ("never overwrites existing files and merges the manifest", "is idempotent: a second run keeps the discovered content"); there is no `--force` flag |
| `sync --apply` writes only what the construct owns: `add` and `update` where the strategy is `create` or `append-block`, and never a `merge-json` target, a `conflict`, an `unknown`, a `removed`, an `orphaned` or a `foreign` path. It deletes nothing — `applyPlan` has no delete — and every byte outside a `construct:begin … end` block, including a filled discovery body, survives | `isWritable` in `src/sync/classify.ts`; `tests/sync-apply.test.ts` ("plans a write exactly where isWritable holds…", "leaves every keep, conflict, removed, orphaned and foreign path byte-identical, path by path", "deletes nothing: the tree afterwards is the tree before plus exactly the add paths it wrote", "carries the body of every discovery marker through byte for byte") |
| A template renders completely or not at all: an unknown `{{variable}}` throws instead of leaving a placeholder in a generated file | `render()` in `src/materialize/templates.ts`; `tests/templates.test.ts` |
| The CLI spawns exactly one child process, `pnpm --version`, with fixed arguments and no shell, and executes no code it did not ship | The `spawnPolicy` `no-restricted-syntax` block in `eslint.config.mjs` fails the build on, anywhere under `src/`: a static `import` of `node:child_process`, any dynamic `import()` expression whatever its specifier, a `require` call or `require.*` member access, a static import of `node:module`, and any `createRequire` identifier; `tests/dependency-policy.test.ts` lints one source sample per form through ESLint and asserts the block still carries the antfu base restrictions. **One file is outside the block:** `src/detect/package-manager.ts`, which carries the spawn, is in the block's `ignores`, and ESLint's `ignores` removes the whole config object rather than one selector — so the code-loading forms are unrestricted there too. It uses none, and nothing mechanical holds that; read it first when this boundary is under review |
| `doctor` executes nothing from the repository it inspects: it derives every verdict from reading file text over a declared read set, so auditing an untrusted clone never runs that clone's code (and no verdict can claim L4) | The same `spawnPolicy` block, with the same single exemption, and [0007](decisions/0007-doctor-executes-nothing.md); `tests/dependency-policy.test.ts` lints one sample per form; `tests/doctor-fixtures.test.ts` asserts no verdict is L4; `tests/doctor-report.test.ts` asserts the report states the boundary instead of a verdict about the harness |
| Every read of an inspected repository under `src/commands/doctor/` goes through one reader, which reports a path it could not read instead of dropping it from the set it inspected | The `doctorReadsThroughOneReader` block in `eslint.config.mjs` forbids `readFileSync` and `readdirSync` under `src/commands/doctor/**` except `readings.ts`; `tests/doctor-readings.test.ts` |
| `init` writes only under the target directory; every target path comes from the package's own `templates/` tree, never from user input | review (`applyPlan` joins `root` with template-derived targets; no path in a template starts with `..`) |
| Templates carry no secret: workflows reference `${{ secrets.* }}` and `CODE_REVIEW_API_KEY` by name only | `.github/workflows/security.yml` runs gitleaks over `templates/**` too; review |
| Nothing published carries a personal filesystem path or a third-party domain nobody put on the list: `templates/`, `docs/`, `README.md` and `tests/fixtures/` (where frozen manifests from other repositories live) are scanned for `/Users/…`, `/home/…`, `~/…` and any host outside the allowlist | `pnpm privacy:check` (`scripts/privacy/check.ts`) is a step of `pnpm run quality`, so it gates every change and every release; the allowlist is `scripts/privacy/allowlist.ts`; `scripts/tests/privacy/scan.test.ts` fails the guard against a fixture per form, and `scripts/tests/privacy/package-files.test.ts` asserts the published package carries no run or findings data |
| `cost` reads Claude Code session files under `~/.claude/projects/<this dir>` and aggregates token counts only; no message content is printed or stored | `tests/cost.test.ts`; review |
| A release is a reviewed, versioned event: `npm publish` runs only from `release.yml` / the `release` script with provenance, never from a developer shell against `main` | review; `.github/workflows/release.yml` |
