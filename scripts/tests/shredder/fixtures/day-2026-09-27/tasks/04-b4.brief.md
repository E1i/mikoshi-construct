Worktree: ../mc-mutate-report

/implement construct mutate judge reads a test report through a format-neutral interface, Vitest JSON or JUnit XML, and refuses a report with no run start time.

Effort: medium — a new judge option in the public contract (contract/surface.json via `pnpm contract:update`), a neutral report module shared by doctor and mutate, and a JUnit start time; the design is written here.

Design:
- A neutral module under src/model/ (for example test-report.ts) owns TestReport, ReportedFile, ReportedTest, Failure, ReportUnreadable and the operations over a TestReport: failuresOf, testCount, testsNamed, wasExecuted. src/model/vitest-report.ts keeps only the Vitest parsing (parseVitestReport, readVitestReport); src/model/junit-report.ts only the JUnit parsing. No re-export from vitest-report.ts: every importer (coverage.ts, junit-report.ts, mutate/judge.ts, mutate/index.ts, tests/junit-report.test.ts) imports from the neutral module.
- One reader chosen by format, as src/model/coverage.ts:33–37 does today: a function in the neutral module (or beside it) takes a ReportFormat from REPORT_FORMATS and returns the TestReport; coverage.ts and judge.ts both call it, so the dispatch has one owner.
- The run start time is part of the interface: TestReport.startTime is a number, or null when the report does not say when the run started. Vitest reads it from startTime as today. JUnit reads the earliest timestamp attribute of its <testsuite> elements, parsed with Date (an ISO timestamp without an offset is local time); no timestamp, or none that parses, is null. Never the report file's mtime: a copy or a touch sets it, so it says when the file was written, not when the run started. Never 0.
- judge takes --format (vitest-json | junit-xml, default vitest-json), for --baseline and for --id alike. A report whose startTime is null is refused as report-unreadable with a detail that names the missing run start time, and nothing is recorded; the existing freshness check (a report that started before the mutation was applied is no witness) is unchanged.
- doctor does not need a start time: a JUnit report with no timestamp reads exactly as today for report-covers / report-misses.
- The descriptions of judge and --report in src/program.ts stop saying "Vitest JSON" and name both formats; lore.ts mutateApplyNext (:374 and its PLAIN_LORE twin :579) stops prescribing the Vitest reporter flags as the only way; docs/cli.md says how each format gives its start time. contract/surface.json only through `pnpm contract:update`; the changeset level is the one `pnpm contract:bump` requires.
- Every new behaviour ships its test in tests/ in the same change: the JUnit start time (timestamp, earliest across suites, none → null), judge --format junit-xml (baseline and id), the refusal naming the missing start time, the freshness check on a JUnit report; each new test is red on the base and green after. The gate does not check this yet (#269), so the implementer must.
